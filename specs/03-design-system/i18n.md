### 1.2 O Único Uso de `intl` — Formatação de Dados

O pacote `intl` está presente no `pubspec.yaml` e é usado **exclusivamente** para formatar datas e números no padrão brasileiro:

```dart
// lib/src/core/utils/formatar_valores.dart
import 'package:intl/intl.dart';
import 'package:intl/date_symbol_data_local.dart';

class FormatarValores {
  // Formata número como moeda BRL
  String priceToCurrency(double price) {
    NumberFormat numberFormat = NumberFormat.simpleCurrency(locale: 'pt_BR');
    return numberFormat.format(price);
  }

  // Formata número decimal no padrão BR (ponto como separador de milhar, vírgula decimal)
  String formatvalueToBrasil(double values) {
    NumberFormat numberFormat = NumberFormat.currency(locale: 'pt_BR', symbol: '');
    return numberFormat.format(values).trim();
  }

  // Formata DateTime como "dd/MM/yyyy HH:mm" em PT-BR
  String formatDateTime(DateTime dateTime) {
    initializeDateFormatting();
    DateFormat dateFormat = DateFormat.yMd('pt_BR').add_Hm();
    return dateFormat.format(dateTime);
  }
}
```

> **Conclusão:** `intl` é usado como utilitário de formatação numérica/de datas, **não** como sistema de internacionalização de strings de UI.

## 3. Infraestrutura de i18n para o Template

> ⚠️ **Consideração futura (NÃO aplicar agora).** A direção atual é preservar a stack e os padrões existentes (ver [documentation-stance](../00-overview/documentation-stance.md)). As seções 3.1–3.8 abaixo documentam uma infraestrutura de i18n que poderia ser adotada no futuro — o projeto atual usa `intl` apenas para formatação e strings PT-BR hardcoded, o que é o padrão preservado.

### 3.1 Stack (alternativa futura)

```
flutter_localizations (SDK Flutter — sem versão separada)
+ intl: ^0.19.0 (já presente)
+ gen-l10n (ferramenta do Flutter SDK — flutter gen-l10n)
```

### 3.2 Estrutura de Arquivos Proposta

```
lib/
├── l10n/
│   ├── app_pt_BR.arb    ← idioma padrão (PT-BR)
│   └── app_en.arb       ← inglês (opcional para template)
└── core/
    └── l10n/
        └── app_localizations.dart  ← gerado por gen-l10n
```

### 3.3 `pubspec.yaml` — Alterações Necessárias

```yaml
dependencies:
  flutter:
    sdk: flutter
  flutter_localizations:        # ADICIONAR
    sdk: flutter
  intl: ^0.19.0                 # já presente

# ADICIONAR ao final do arquivo:
flutter:
  generate: true                # ativa gen-l10n
```

### 3.4 `l10n.yaml` — Configuração do Gerador

Criar arquivo `l10n.yaml` na raiz do projeto:

```yaml
arb-dir: lib/l10n
template-arb-file: app_pt_BR.arb
output-localization-file: app_localizations.dart
output-dir: lib/core/l10n
nullable-getter: false
```

### 3.8 Manutenção da Formatação com `intl`

O uso atual de `intl` para formatação numérica e de datas está **correto e deve ser mantido** no template:

```dart
// Manter como está — é a abordagem correta
NumberFormat.simpleCurrency(locale: 'pt_BR').format(price);
DateFormat.yMd('pt_BR').add_Hm().format(dateTime);
```

A locale `'pt_BR'` pode ser tornada dinâmica futuramente:

```dart
// Versão dinâmica (fase avançada do template)
final locale = Localizations.localeOf(context).toString(); // 'pt_BR' ou 'en'
NumberFormat.simpleCurrency(locale: locale).format(price);
```

## 5. Pontos Fortes do Legado Aproveitáveis

1. **`intl: ^0.19.0` já está no `pubspec.yaml`** — sem necessidade de adicionar nova dependência principal.
2. **`FormatarValores` já usa `locale: 'pt_BR'` corretamente** — modelo que deve ser seguido no template.
3. **`PlutoGridLocaleText` já configurado em PT-BR** — trabalho manual valioso; deve ser extraído como constante reutilizável `PlutoGridPtBrLocale`.
4. **Consistência de idioma nas strings de negócio** — quase tudo em PT, facilitando a criação do `.arb` inicial.
